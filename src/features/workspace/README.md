# Workspace and sessions

`useWorkspaceSessions` owns the workspace sections, the session lists they contain, and the active workspace. It coordinates refreshes, creation, reopening, renaming and closing, optimistic naming, pending UI requests, and persisted workspace, selection, and collapse state. Completed-session indicators last for the current browser tab.

There is no main workspace. Sections are built by `workspace-groups.ts` from persisted history rows, live Pi sessions, and folders the user added explicitly, ordered by newest activity. A live session stays visible before its history row is written. A section is named after its folder basename and qualified by its parent only when two sections share it. `workspacePaths` keeps created or opened folders so a section survives even when it has no sessions left, and its order drives the previous-workspace command. The backend returns up to 30 history rows per workspace.

The active workspace follows the selected live session and falls back to the last one used, which keeps Git, todos, terminal, prompt templates, and the right sidebar in a stable context while the user browses sections. `App.tsx` receives that path as `workspacePath` and supplies cross-feature callbacks such as resetting workspace-scoped state; it must not duplicate the controller's state.

Sessions are created through `NewSessionDialog`, which reaches the host's native folder dialog through `pickDirectory()`, or from the `＋` button of a section. The dialog is labelled `New session`; recent workspaces remain in the sidebar rather than being repeated in the picker. A section lists its four most recent sessions and reveals the rest through a `Show N more` row; collapsing the section resets it to four. A session selected from outside the list, such as the restored session or a sibling shortcut, reveals the section that holds it once; a session created from a section's `＋` button leaves that section's collapse state untouched. Typed paths with completion stay available because a headless host may not provide any native dialog. Workspace paths accept both `~/...` and Windows `~\...`; `directory-completion.ts` preserves the separator style the user typed.

Right-clicking a session row (or pressing the context-menu key) offers Rename, Archive or Unarchive, Close session while Pi runs it, and Delete. Archiving closes a running session and moves the row under the section's `Archived (N)` toggle; opening an archived row unarchives it. Archived session paths persist in `pi-livecraft.archived-sessions`; archived rows still count toward a section's activity order so archiving never reshuffles the sidebar. Delete asks for confirmation, closes a running session, and removes the Pi session file through `POST /api/sessions/delete`, which refuses a session that is still open. Right-clicking a section header renames the workspace in the sidebar only; names persist in `pi-livecraft.workspace-names`, and the folder on disk is never renamed.

Pure list, naming, and grouping rules live in `workspace-groups.ts`; the sibling-navigation rule lives in `sidebar-sessions.ts`.
