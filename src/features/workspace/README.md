# Projects and sessions

`useWorkspaceSessions` owns the workspace sections, the session lists they contain, and the active workspace. It coordinates refreshes, creation, reopening, renaming and closing, optimistic naming, pending UI requests, and persisted workspace, selection, and collapse state. Completed-session indicators last for the current browser tab.

The sidebar header shows a banner and the panel toggle. The banner is the built-in Pi banner (`SidebarBanner.tsx`, an SVG drawn in the theme's colours) or an image the user chose in Settings → Sidebar; `sidebar-banner.ts` scales a chosen image down to 1200×400 at most, stores it as a data URL under `pi-livecraft.sidebar-banner`, and the pencil on the banner opens that tab. Below it a toolbar holds New session, Reload (runs `/reload` for the selected session; disabled with the reason as its tooltip when no session is open, Pi is working, or nothing is saved yet) and Settings. When the sidebar is collapsed, one floating panel button brings it back.

There is no main workspace. Sections are built by `workspace-groups.ts` from persisted history rows, live Pi sessions, and folders the user added explicitly, ordered by newest activity. A live session stays visible before its history row is written. A section is named after its folder basename and qualified by its parent only when two sections share it. `workspacePaths` keeps created or opened folders so a section survives even when it has no sessions left, and its order drives the previous-workspace command. The backend returns up to 30 history rows per workspace.

The active workspace follows the selected live session and falls back to the last one used, which keeps Git, todos, terminal, prompt templates, and the right sidebar in a stable context while the user browses sections. `App.tsx` receives that path as `workspacePath` and supplies cross-feature callbacks such as resetting workspace-scoped state; it must not duplicate the controller's state.

New session offers existing projects and an optional name for a new project. Named projects use a folder under the host's project root (`Documents\AI Projects` in the user's home folder, configurable with PI_PROJECTS_DIR; `server/project-directory.ts`). A blank name uses General. Users can also pick an existing folder. The section's plus button creates another session in that project. Existing history, custom names, archive state, and shortcuts keep their folder-backed keys. A section lists its four most recent sessions and reveals the rest through a `Show N more` row; collapsing the section resets it to four. A session selected from outside the list, such as the restored session or a sibling shortcut, reveals the section that holds it once; a session created from a section's `＋` button leaves that section's collapse state untouched. Typed paths with completion stay available because a headless host may not provide any native dialog. Workspace paths accept both `~/...` and Windows `~\...`; `directory-completion.ts` preserves the separator style the user typed.

Right-clicking a session row (or pressing the context-menu key) offers Rename, Archive or Unarchive, Close session while Pi runs it, and Delete. Archiving closes a running session and moves the row under the section's `Archived (N)` toggle; opening an archived row unarchives it. Archived session paths persist in `pi-livecraft.archived-sessions`; archived rows still count toward a section's activity order so archiving never reshuffles the sidebar. Delete asks for confirmation, closes a running session, and removes the Pi session file through `POST /api/sessions/delete`, which refuses a session that is still open. Right-clicking a section header offers Rename project (sidebar only; names persist in `pi-livecraft.workspace-names`, and the folder on disk is never renamed) and Delete project. Delete project (`ProjectDeleteDialog.tsx`) shows how many saved sessions the project has (`GET /api/projects/delete-info`), closes its running sessions, permanently deletes every Pi session file recorded for the folder (`POST /api/projects/delete`, which refuses while one still runs), and drops the section with its stored name, collapse and archive state. The folder and its files are kept, unless the user ticks the option to move the folder to the Recycle Bin, which is offered only on Windows and only for folders inside the projects root, never for a folder added from elsewhere. A project whose folder no longer exists is simply removed from the sidebar.

Right-clicking anywhere else in the sidebar opens the sidebar menu:

- **New project** opens the New session dialog in project mode (no existing-project choice).
- **New section** adds an existing folder as a project section without starting a session (`AddFolderDialog.tsx`, then `addWorkspacePath`).
- **Select all** turns on selection mode: rows show check boxes, a click selects instead of opening, and a toolbar offers All, Archive, Delete… (one confirmation for every selected session) and Done. Escape leaves selection mode.
- **Group by** switches between Folder (the project sections), Date (Today, Yesterday, Previous 7 days, Older, from local midnight) and None (one list, newest first). Outside the folder view each row also names its project, and section headers have no project actions. The choice persists in `pi-livecraft.sidebar-group-by`.
- **Collapse all** and **Expand all** act on every section. Folder sections keep their persisted collapse state; date and flat sections keep theirs for the current visit.

Pure list, naming, and grouping rules live in `workspace-groups.ts` and `sidebar-grouping.ts`; the sibling-navigation rule lives in `sidebar-sessions.ts`.
